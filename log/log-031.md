# Log 031 — PICO video (FPV) pipeline with an on/off button; built, not used yet (2026-11-01)

## Decision (Suraj)
The pipeline is kept in the code but **not used for now**: the video adds Wi-Fi load (~4 Mbit/s) next to the
controller input, which already has short gaps every ~15 s (log-013). Not tested in the headset.

## What exists
- Video sender: Orboh fork `XRoboToolkit-Orin-Video-Sender`, branch `vector-x86` (the Notion FPV page: the
  official main does not build). Built on this PC 2026-11-01 with `make` (deps were already installed);
  binary `~/projects/XRoboToolkit-Orin-Video-Sender/OrinVideoSender`. H.264 x264 zerolatency, ~29 fps.
- Camera: chest D435i colour stream = `/dev/video4` on this PC (found with `gst-device-monitor-1.0`;
  `v4l2-ctl` is not installed). The D405 colour streams are `/dev/video14` and `/dev/video20`.
- On/off from the VR: **hold the LEFT controller's Y button for 1 s** (A turns the app's sending off,
  B switches the video panel 2D/3D). Inside the teleop sender, because only one program may read the PICO.

## Code
- `pico_teleop/video.py` `VideoToggle`: hold-to-toggle (one toggle per press, short presses ignored),
  starts/stops the child process, reports a video sender that died, log next to the run (`*-video.log`).
- `pico_teleop/sender.py`: `--video-device` (off unless given), `--video-bin`, `--video-port` 13579;
  reads left Y every cycle, logs `video` on/off per cycle, stops the video on exit.
- `scripts/video_check.sh` (dry run, no arm), `scripts/arm_session.sh` with `VIDEO=/dev/video4`.
- Tests `tests/test_video.py` (short press, hold on/off, dead process).
