## Measured input behaviour (the integration contract for the sender)
1. **Rate:** headset samples at ~90 Hz (device clock steps 11 ms); 77-84 Hz arrive. Wi-Fi delivers in
   bursts: gap p50 10 ms, p99 56 ms, 0.5 % > 100 ms, rare 250-346 ms.
   → sender stale threshold raised 0.1 s → **0.25 s** (= receiver hold), else ~25 false FAULTs/min.
2. **Grip reads only 0.00 or 1.00** (a button, not analog). Trigger is analog (0.56 seen).
   → the 0.6/0.4 hysteresis is moot for grip; harmless.
3. **Operator note:** pulling the trigger often squeezes the grip too (seen at 22-23 s in phase 2).
   Accidental grip = an engage (no motion by itself). Proposal: require the grip held ≥ 0.3 s to
   engage. Not implemented yet (decision: Suraj).
4. **A controller lying on the table freezes:** its pose becomes bit-identical within ~2 s (both
   sides, phases 1, 2, 5). Held controllers never repeat a pose. → "frozen" works as "not held".
5. **A hidden controller is NOT flagged:** behind the back the pose stays valid, position nearly
   constant (< 1 mm/s), rotation still updating; no zero, no frozen, no flag. Not distinguishable
   from holding still in view. On return the pose catches up (46 cm in ~1 s in phase 4).
   → cannot be detected from the stream. Mitigations: speed limits (catch-up at ≤ 0.25 m/s TCP),
   runbook rule "open the grip before the hand leaves the view", proposed jump FAULT (not built).
6. **Headset off:** the stream keeps running ~8 s, then stops (sleep) → stale → FAULT in the sender.
   On wake the first poses read (0,0,0) → caught by the `origin` status.
7. No timestamp went backwards; no non-finite values; no bad quaternions in any run.
