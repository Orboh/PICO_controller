# Log 042 — Page keys did not reach the recorder: lerobot used the global keyboard because of DISPLAY (2026-11-01)

## Symptom (Suraj)
"It does not stop after one episode … I pressed Next episode": the run `~/collections/20261101T115231Z-pilot-pico`
has **no episode** (no "録画中"); its console shows only "Waiting … press → to start" and **28** `a` key presses (correction: not three). The follower was **powered and connected** ("Connected to can_fol_l", "follower_left OpenArmFollower connected", 20:52); the log stops at 21:00:51 with no normal end and the manifest unresolved (how it was stopped is not recorded).
Earlier "End recording does not end" (log-041) had the same cause in addition to the CAN crash.

## Cause
lerobot `common/control_utils.py init_keyboard_listener()`: with `DISPLAY` / `WAYLAND_DISPLAY` set (the GUI runs in the
desktop session, DISPLAY=:1) it reads → ← Esc from the **global desktop keyboard (pynput)**, not from its terminal; only
the fork's `a` also comes from the terminal. Bytes typed into the pty were echoed (`^[[C`) and ignored. Proven with
lerobot's own listener in a pty: without DISPLAY → "Right arrow key pressed", with DISPLAY=:1 → nothing.
(Side effect of the old way: any → pressed on the PC's keyboard, in any window, would have driven the recorder.)

## Fix
`session.recorder_command` removes `DISPLAY` and `WAYLAND_DISPLAY` for the recorder (value None; `PtyChild` drops
None keys from the child's environment). lerobot then prints "No display detected: reading recording control keys
from stdin" and the page's keys work. Camera preview is off anyway (`DISPLAY_DATA=false`).
Tests: `test_recorder_runs_without_a_display`, `test_right_arrow_reaches_lerobots_real_key_reader` (end to end with
lerobot's listener). The GUI must be restarted; the recording that was running used the desktop keyboard.

## Same fix at the script level (Suraj: "fix the bug with the existing method")
All collection programs use lerobot-record's keys (survey in the reply of 11-01): `collect_bimanual.sh` already starts
the recorder with `env -u DISPLAY -u WAYLAND_DISPLAY` (line 141), so the Collect tab was never affected; our single-arm
path (`record_pick_place_openarm.sh`) did not. Now `scripts/pilot_record.sh` and `scripts/gate4_record.sh` do the same,
so a terminal run reads → ← a Esc from its own terminal like the page (no more keys from the desktop keyboard in any
window). The page keeps removing DISPLAY too (harmless twice).
Proposal for a key-free control (a command channel in the lerobot fork's record loop) → Kento-san (Slack draft in the
