## Options and choices
| Question | Options | Chosen | Why |
|---|---|---|---|
| Clutch | trigger / grip / button toggle | **grip, hold-to-follow**, hysteresis 0.6 / 0.4 | goal proposal; releasing = stop is the natural reflex; toggle can be left on |
| Gripper | grip / trigger; binary / analog | **trigger, analog**, 0 → -60°, 1 → 0° (closed) | separate from the clutch; -60° is the draft's value from the 2026-10-26 data (not re-measured) |
| Gripper at engage | follow the trigger at once / soft takeover | **soft takeover** | the start pose has gripper 0 (closed); a released trigger would open it suddenly |
| Mapping | absolute / relative | **relative to an anchor**, scale 0.5 | first command = current target exactly; head/body position irrelevant |
| Orientation | 6-DOF now / position only | **position only** | goal: add the wrist only after position is validated |
| Unreachable / singular / branch flip | clamp and continue / fault | **FAULT, release to clear** | goal: stop advancing, deliberate re-engagement |
| Grip held at start | engage / wait for a release | **wait** ("armed") | a held grip at launch would otherwise start following |
| IK seed and jump check | from the sent joints / from the last IK answer | **last IK answer** | the sent joints lag (rate limit) → false "jump" faults at 22 cm (found in the plots) |
| IK tolerance | stop at 5 mm / solve to 0.1 mm, accept ≤ 5 mm | **solve fine, accept 5 mm** | stopping at 5 mm made a staircase: 0 / 0.9° steps (found in the plots) |
| Lag bound | none / hold the TCP target while lag > 10° | **hold the target** | joints never trail the IK answer by more than 10° |
| Null-space limit push | off / on (band 15°) | **off** (code kept) | on: the arm moved at engage (right joint_2 starts 7° from its limit) and joint_2 swung 75° |

Starting numbers (all to confirm on hardware): 50 Hz; TCP ≤ 0.25 m/s; joints ≤ 45°/s (validator
allows 60 × 1.5 per cycle); gripper ≤ 120°/s; σ_min ≥ 0.03; jump ≤ 20°; margin 2°.

## Findings
1. **Right arm, takeei-v2 start pose:** a 5 cm TCP circle toward the body drives right joint_1 to
   its limit (-78° with margin) at about 2.2 s; the position-only IK then swings joint_2 by about
   60° to keep the TCP on the circle. Smooth and within the rate limits, but a big posture change for
   a small hand motion. Not a bug in the solver: 4 free DOF with joint_1 and joint_2 both near limits.
   Remedies: wrist orientation hold (later milestone), a posture-change fault, or a different start
   pose. **Must be seen in a visualizer (Meshcat) before hardware.**
2. Joint 2 of both start poses sits within about 7 to 9° of its limit (left -1.2° vs 8°; right -0.7° vs -8°).
3. The XR→robot axis matrix assumes the operator faces the robot's +x. Confirm the signs live.
4. Right-arm zero and sign are still unverified on hardware (as in log-002).
