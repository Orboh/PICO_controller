# Log 013 — Periodic input stalls: investigation, Wi-Fi power save, stale limit 0.25 → 0.4 s (2026-10-31)

## Problem (from the arm sessions, log-010/011)
PICO input stalls of 0.22-0.34 s **about every 15 s** (both arm sessions and the online gate-3 run).
With the sender's stale limit at 0.25 s, about half of them FAULT an engaged arm (2 per session).

## Investigation
| Step | Result |
|---|---|
| PC Wi-Fi power save | NetworkManager `/etc/NetworkManager/conf.d/*powersave*` had `wifi.powersave = 3` (ON). Suraj turned it off for `orboh`: `sudo nmcli connection modify orboh 802-11-wireless.powersave 2 && sudo nmcli connection up orboh`; `nmcli -g 802-11-wireless.powersave connection show orboh` → `disable`. PC kept 192.168.0.136. |
| 60 s input measurement after that | 4838 updates (~81 Hz), gap p50 10.6 ms, p99 64.6 ms, max 331 ms; > 100 ms 0.70 %; **> 200 ms at 1.7, 16.6, 32.2, 46.5 s** → still every ~15 s. PC power save was not the cause (kept off anyway). |
| Ping PC → PICO 30 s (`ping -i 0.05`) | 633 replies, a few 103-135 ms, **no periodic 300 ms stalls** → the Wi-Fi link is fine. |
| Conclusion | the 15 s stall is most likely **inside the headset / XRoboToolkit app** (a periodic task). Not fixable from the PC. Open: check PICO settings (Wi-Fi power saving, background scan) or ask XRoboToolkit upstream. |

## Change: stale limit 0.25 s → 0.4 s (Suraj's decision)
- `pico_teleop/sender.py`: new `--stale-s` (default **0.4**) → `FreshnessTracker(stale_s=a.stale_s)`.
- Why it is safe: while the input is stale the controller's target does not advance (no new hand
  pose), so the arm holds; when data returns, the **one-update hand-step FAULT (> 10 cm)**, the 3 m/s
  speed FAULT, the 15 cm lag FAULT and the 0.25 m/s TCP / 45°/s joint limits catch any jump. The
  diagnostic keeps 0.1 s (it measures, it does not drive).
- Headset off still stops the stream after ~8 s → stale → FAULT; a lost receiver is unaffected
  (separate link timeout).
- Evidence: replay of session 2's real input (`runs/arm-c2-20261031-sender.jsonl`) through the
  sender logic, dry: **stale 0.25 s → 6 engages, 2 stale FAULTs; 0.4 s → 6 engages, 0 FAULTs**
  (and, with the 60° posture limit, no posture FAULTs either). README message table updated.
- Tests: **72 passed**.
