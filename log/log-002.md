## Integration contract (from code, which wins over documents)
- Packet: `{"seq", "t_mono", "arm", "action": {"joint_1.pos".."joint_7.pos", "gripper.pos"}}`, degrees,
  ZMQ PUSH + CONFLATE=1 + LINGER=0, connect to `tcp://<follower>:5701` (right) / `5702` (left).
  Echo back from the receiver on 5711 / 5712: `{"seq","t_mono"}`, or `{"cmd":"soft_move_to",...}`
  (record 'a' key) — `openarm_leader_remote.py:227-283`.
- Receiver `connect()` waits up to 30 s for the first packet and requires all 8 keys; the first
  packet becomes the held target (`:114-139`). Stale > 250 ms → hold last; resume → 1 s linear ramp.
- Follower `send_action` clips to `joint_limits` (= URDF limits per side) and has
  `max_relative_target=None` by default (`openarm_follower.py:438-452`).
- Follower `connect()` aligns to the pose-set start pose (`--robot.initial_pose_path`), ~2.2 s.

## Findings that shape the design
1. **NaN goes to the upper limit.** The receiver does `float(value)` with no finite check, and the
   follower clips with `max(lo, min(hi, x))`; for x = NaN, Python returns `hi`. → the sender must
   reject non-finite values itself (`validate.py`).
2. **Doc vs code:** the request §2.2 says the receiver "checks that the first pose is within joint
   limits". The code only checks that keys exist. → the sender validates its first packet too.
3. **No follower feedback to the sender.** The echo path carries seq/t_mono only. The sender cannot
   see where the follower is. The safety protocol (§1 L0) asks for a tracking-error guard
   (|measured − commanded| > 8° → stop), which needs that feedback. → open gap, see log-004.
4. **Right arm ≠ mirrored left.** Right joint7 is a pure Y axis, left joint7 is not; the joint limits
   differ per side. Both sides' URDF limits equal lerobot's `{LEFT,RIGHT}_DEFAULT_JOINTS_LIMITS`, so
   lerobot degrees = URDF degrees, same zero and sign (on paper; the right-arm zero/sign is not
   verified on hardware, the left only for joint_1/4 per `ik/README.md`).
5. **SDK keeps stale values** and updates each controller only when present in the packet; the
   timestamp is shared (`py_bindings.cpp:115-155`). Before any data everything is zero.
6. **Gripper:** lerobot range (-65, 0) deg, 0 = closed (calibrated closed). The start pose sets
   gripper 0 on purpose (a non-zero grip command at startup once broke the follower gripper).
7. **Branch:** the request names `dev/openarm-vla`, but `main` (9f0398d) is newer; the old Notion
   setup guide names a retired lerobot branch (request §5 says so itself).
