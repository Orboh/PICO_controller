## New requirements from the operators (next development)
1. **Wrist rotation (orientation control).** Today the IK is position-only: the hand's rotation is
   ignored and joints 5-7 only help reach the position. Plan: map the controller's rotation (relative
   to the engage pose) to the gripper orientation, 6-DOF IK with a weight on orientation; frames are
   OpenXR right-handed (log-008), so `controller_in_robot`'s R·M·Rᵀ is valid. Steps: offline tests +
   plots → dry run with the headset (rotate the hand, check the printed gripper rotation) → arm.
2. **Gripper force ("power") feedback.** Two parts:
   - *Sensing*: the follower's gripper torque/position must reach the sender → needs the receiver
     feedback patch (`proposals/lerobot-follower-feedback.patch`, owner Kento), extended with
     `gripper.torque` (follower `use_velocity_and_torque`).
   - *Telling the operator*: the PICO pybind SDK has **no vibration/haptics call**. The C SDK has
     `PXREADeviceControlJson` / `PXREASendBytesToDevice` (generic "send to device"); whether the
     XRoboToolkit PICO app supports a vibration command is undocumented here → check upstream
     (XR-Robotics repos/issues) before building. Fallback: a visible/audible cue (sound on the PC,
     or the gripper force shown in the headset video overlay).
   - Also possible without feedback: a **gripper force limit** (cap the closing command when the
     gripper stalls on an object) to protect objects and the gripper.
